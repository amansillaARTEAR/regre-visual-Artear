Configurar acceso

Este dashboard corre 100% en tu navegador (GitHub Pages no tiene backend), así que necesita un token de GitHub para poder disparar workflows y leer los reportes de un repo privado. El token se guarda únicamente en el localStorage de tu navegador — nunca sale de acá salvo hacia api.github.com.

Crealo en GitHub → Settings → Developer settings → Fine-grained tokens, con acceso a ambos repositorios (regre-visual-artear y Mobile-Artear — se pueden elegir varios en "Only select repositories") y permisos: Actions: Read and write, Contents: Read and write. Sin esos dos permisos el dashboard no puede disparar corridas ni leer los reportes.

Disparar corrida — iOS (AWS Device Farm)

Corre la suite contra un iPhone real de AWS Device Farm. Requiere crear la sesión a mano primero (no se puede automatizar esa parte: la cuenta de AWS no tiene una Access Key habilitada).

  1. Andá a la consola de Device Farm → proyecto "Ale M" → pestaña "Remote access".
  2. Creá una sesión nueva ("Create remote access session") con un iPhone.
  3. Una vez que arranca, copiá la URL del Appium endpoint de esa sesión.
  4. Pegala acá abajo y disparás. La sesión de AWS sigue corriendo mientras dure el test (se cobra por minuto).
Corre los casos tildados en "Casos de prueba" más abajo (ninguno tildado = suite completa).

No se activa solo: abre un Pull Request para que lo revises antes de sumarlo a la suite — puede necesitar ajustes si el ticket pide algo que ningún caso probó antes.

Corre en un runner normal de GitHub (no hace falta tu PC prendida para esto). Cuando termine, el link al Pull Request va a aparecer en "Corridas recientes" de abajo → "ver en GitHub".
